程式邏輯與互動方式（最新版）
--------------------------------------------------------------------------------

  • 章節資料：Play 頁依 chapterId 呼叫 getChapterData('ch1')，取得 scenes / items / npcDialogs 後 engine.loadChapterData(data)，不直接 import 完整 gameData。
  • 場景進入：每個場景 initialDialog 進入時顯示；劉隊階段一（第一次進入 ch1 任一場景）觸發 reasoningByChapter.ch1.police.introLines，寫入 ch1_police_intro_shown。
  • Hotspot 點擊：handleHotspotClick → 先 handleItemCollection(hotspotId)。若該 hotspot 對應事件含 addItem，則觸發事件、顯示道具浮動卡（activeItemDetail）並將事件內 showDialog 排入 dialogQueue；否則走一般事件流程。角色對話（talk_to_character_* / character_*_talk）由 CharacterConversation 系統載入 data/characterConversations.ts。
  • 道具取得：取得時僅顯示浮動詳解卡（與背包點擊同一套），不把「獲得：xxx」排入一般對話佇列；事件的 showDialog（線索說明／旁白）會排入隊列依序播放。
  • 敏感抉擇：sensitiveGate 顯示「問敏感」入口；完成任一人敏感對話後寫入對應 npc_*_sensitive_done；完成至少三次寫入 ch1_liu_mid_ready，觸發劉隊中段問候並設 ch1_liu_mid_shown，解鎖劉隊頭像。
  • 劉隊頭像：階段二+ 點擊後「初步看完了嗎」→ 選「整理一下」或「再繞繞」；階段三選「向劉隊報告」需 readyToReport（hasCh1CoreClues + allScenesVisited）→ setShowCh1ReportEditor(true)。
  • 報告流程：Ch1ReportEditor 四步驟（證據桌 → 時間線 → 版本深度 → 態度宣言），完成後 setReasoningComplete('ch1')，寫入 ch1_reasoning_done 並導向 /play/ch2/intro。ch1 不顯示右下角「推理分析」按鈕，章末僅能經「向劉隊報告」完成。

序章文案（逐句，與 data/chapters.ts prologueSlides 一致）：

  凌晨00:39，你的手機震了一下。
  一通沒有顯示來電的電話，像城市不想留下指紋。
  「KK？」對方壓低聲音，「偵查隊。需要你來一趟。」
  你坐起來，窗外的霓虹還亮著，像一部不肯散場的電影。
  「哪裡？」
  「城市影城。散場後大概五分鐘左右，有一名看電影的人，死在H排12號。頸部壓迫，幾乎沒有掙扎。」
  你沒立刻回話，靜靜地聽著。
  對方接著說，像把真正的刀遞到你手上：
  「散場的燈，似乎延後三分鐘亮起。」
  你不是警察，也不是英雄。你只是KK。
  一個警方私下非常信任的外部偵探。
  你拉上外套，拿起筆記本，展開了一個新的任務。

--------------------------------------------------------------------------------

  標題：第一章：城市影城
  副標題：死在散場之後的人

  描述（與 data/chapters.ts ch1.intro 一致）：
  散場後人群聲很吵。塑膠杯、手機光、鞋底黏住地毯的聲音。可這個人死得太安靜。

  散場後最暗的不是影廳。是每個人都想快點回到「正常」。而兇手，似乎就是在正常裡動手。

  KK：「散場的燈，為什麼晚亮三分鐘？」

  KK（旁白）：他把「人」藏進「流程」。

  [繼續]

  KK：「你說流程正常，但流程正常的人不會死得這麼安靜。」
  林瑞堂：「那種調整…上面有上面的考量啦。可能只是服務調整。」

  林瑞堂（真遺憾）：「我真的很遺憾…可我也不想看到這裡被毀掉。」
  KK：「被毀掉的不是影城，是那個人。」
  林瑞堂沉默。

階段四：向劉隊報告 — 報告編輯器（Ch1ReportEditor，data/ch1ReportConfig.ts）

  概念：玩家點擊劉隊頭像且條件滿足時，可選「我想向你報告」→ 直接開啟 Ch1ReportEditor（全螢幕模態）。報告流程為四步驟，全部完成後呼叫 setReasoningComplete('ch1')，寫入 ch1_reasoning_done 並導向 ch2 intro。

  報告入口條件（readyToReport）：

    • Step1 時間線 → 寫入 ch1_report_timeline

  【Step0 — 證據桌】（ch1ReportConfig.evidence）

  玩法：6 張證據卡選 3 張，須涵蓋三類各至少 1（TimeAnchor / ProcessAnchor / PhysicalTrace）。選錯類別時顯示 missingCategoryHints，不說「錯」，只說缺哪種支點。

  證據卡（與道具對照 CH1_EVIDENCE_CATEGORIES）：
    時間支點 TimeAnchor：電影票根、播映時間表（塗改）
    流程支點 ProcessAnchor：燈控紀錄、放映員的筆記
    殘留支點 PhysicalTrace：黑色塑膠碎片、清潔備忘

  每張卡含：titleShort、reportLine（可寫進報告）、kkComment（KK 私下註解）。evidenceSlots: { count: 3 }。

  缺類別提示：
    TimeAnchor：你還缺一種能寫進報告的支點：時間。
    ProcessAnchor：你還缺一種能寫進報告的支點：權限或流程。
    PhysicalTrace：你還缺一種能寫進報告的支點：殘留或現場痕跡。

  ---

  【Step1 — 時間線】（ch1ReportConfig.timeline）

  玩法：5 張事件卡依正確順序點選。順序錯誤時顯示 errorMessages（KK 吐槽）。

  事件卡與正確順序 correctOrder：
    1. T1_movie_start_2240 — 22:40 電影開演
    2. T2_normal_lights_0015 — 00:15 原訂散場亮燈（排程表）
    3. T3_modified_lights_0018 — 00:18 實際亮燈（延後約三分鐘）
    4. T4_cctv_shadow_001630 — 00:16～00:30 監視器陰影區無有效畫面
    5. T5_call_0039 — 00:39 報案電話

  錯誤回饋例：時間線對不上，再排一次。／順序錯了——先想誰能控制燈、誰在黑暗裡。／首尾可以固定：開演、報案。中間三張再想想。

  crimeTimeRange: { startMinutes: 14, endMinutes: 17 }（撥鈕選中時間落在此區間內通過，單位：當日 00:00 起算分鐘）。

  【Step2 — 版本深度】（ch1ReportConfig.version）

  玩法：劉隊標準結論（見 reasoningByChapter.ch1.police.outroStandard）後，玩家可選擇是否補一句進報告。選「先不用」或任一句後寫入 ch1_police_note（id 或 none）。

  劉隊標準結論（outroStandard）：

  playerLineOptions（ch1ReportConfig.version）：
    • none — 先不用，就照你寫的版本。
    • ch1_summary_flow — 燈不是自然晚，是被人改過。表格、手動模式、口頭指示……流程這次站在兇手那邊。
    • ch1_summary_human — 我想知道誰在遮蔽，遮蔽的原因。
    • ch1_summary_evidence — 現場乾淨得太刻意。有人花力氣把痕跡擦掉，卻忘了碎片比血跡難處理。
    • ch1_extra_report — 至少寫進去：這樣的燈光調整與清場節奏，未來若不被檢討，仍可能致人於死。

  玩法（二擇一，目前實作為四選一內容卡）：

    • 內容卡：attitudeContainers 為「警用報告封套」「KK 私人備忘錄」；attitudeContentCards 四張選一，須將 requireInMemoCardId（ch1_attitude_both）放進 KK 備忘錄。

  四張態度卡（影響 insights）：
    • ch1_attitude_procedure — 「體制要查就查到底。別讓他們用『疏失』兩個字收工。」→ procedure_insight +1

    • ch1_attitude_human — 「我想知道是誰在幫兇手擦地板。恐懼比刀子還好使。」→ human_insight +1
    • ch1_attitude_both — 「上報歸上報，我自己的備忘可不會只寫『疏失』。兩邊都留。」→ procedure_insight +1、evidence_insight +1

  • ch1_liu_mid_shown：階段二中段問候已播，解鎖劉隊頭像（可點擊）；劉隊出現條件 availabilityRequirement.hasFlag ch1_liu_mid_shown。
  • 報告入口 readyToReport = hasCh1CoreClues && allScenesVisited（且 chapterId === 'ch1'）；選「我想向你報告」ch1_liu_report_now → setShowCh1ReportEditor(true)。
  • ch1_report_evidence、ch1_report_timeline、ch1_police_note、ch1_attitude_declared：報告編輯器四步驟依序寫入。
  • ch1_reasoning_done：僅在 Ch1ReportEditor 完成態度宣言並按下「進入第二章」時，經 setReasoningComplete('ch1') 寫入；同時設 navigate_to_ch2_intro，頁面 router.push('/play/ch2/intro')。
  • ch1 不顯示右下角「推理分析」按鈕；章末僅能經「向劉隊報告 → Ch1ReportEditor」完成第一章。

  • gameDataCh1 場景內謎題（保留，主線不經此入口）：放映廳 puzzles 含 puzzle_ch1_how_murder_happened（input，解為「延後亮燈3分鐘」）、ch1_pair_matching（pick_three，三組道具組合）、ch1_reasoning_1/2/3（arrangement 字詞排列）。解鎖 chapter2 主線以 setReasoningComplete('ch1') 為準。
  • 章節資料載入：getChapterData('ch1') 回傳 gameDataCh1 的 scenes / items / npcDialogs；play 頁載入後 engine.loadChapterData(data)，scenes、items 由 engine.getScenes()、engine.getItems() 取得。
